# 架构总览

> Cleat 面向**授权的安全测试与红队演练**。本文描述其整体结构、组件边界与三大核心设计。

## 1. 三个组件

| 组件 | 语言 | 职责 | 平台 |
| --- | --- | --- | --- |
| **Agent** | C++17 | 落地端：通信、任务调度、通道链、睡眠掩码、模块执行 | Windows（主线）/ Linux |
| **TeamServer** | Go | 多操作者服务端：监听器、会话管理、任务分发、存储 | 跨平台 |
| **cleat-web** | React + TypeScript | 操作台前端：会话、任务、凭据、监听器管理 | 浏览器 |

```
Agent/          C++ 落地端
  Core/         通信、会话、通道、掩码、任务、模块、安全
  Components/   功能组件（Pivot 转发 / Shell / 文件传输 / 系统信息）
  Common/       协议、日志、第三方单头依赖
TeamServer/     Go 服务端（API + 控制台静态资源 + SQLite 存储）
cleat-web/      前端
scripts/        依赖构建脚本（libsodium / msquic）
docs/           本文档集
```

## 2. 三大设计核心

Cleat 的差异化集中在三个"平面"，各自解决一类工程难题：

### 2.1 数据平面 —— 混合帧协议

`JSON 头 + 0x00 + 二进制载荷`：帧边界由 JSON 规范背书（合法 JSON 文本不存在裸 `0x00`），
头部自描述、载荷不透明。由此获得：中继节点只读头部即可路由转发、状态机复杂度收敛进
格式规约、二进制载荷零膨胀（文件传输/模块下发/BOF 参数）。

### 2.2 控制平面 —— 运行时通道链

多通道不是编译期写死，而是**运行时**的优先级链：

- **链序即优先级**：候选通道按顺序降级（连续失败达阈值切换），降级后按间隔**回探**高优先
  候选，成功即回切；`min_hold` 防 A/B 震荡
- **原子换链**：`SetConfig` 远程下发新链 → 修订号递增 → 会话循环感知 → 重建候选链并
  原子替换，无重启、无停连
- **切换不丢会话**：会话确认层在通道之上，换链后按既有路径重发注册帧；在飞请求由帧头
  的会话身份兜底

通道类型：HTTPS / TCP / DNS（含 DoH，RFC 8484）/ ICMP / WebSocket / QUIC（可选，默认关闭）。

### 2.3 时间平面 —— 条件睡眠掩码

空闲期将**整个自身镜像加密驻留**（timer-chain 窗口），多线程下以"停靠协议 + fail-closed
普查"保证窗口期安全；并且**只在低频 Poll 型通道启用**（变色龙策略）——低频保活时把内存
也藏起来，高频作业时不折腾。

## 3. Agent 运行时

- **会话主循环**：`连接 → 注册 → 就绪` 的状态推进；退避与抖动；换链感知；掩码窗口编排
- **命令面**：帧分类（纯函数）→ 路由 → 命令队列 + 工作线程；`request_id` 关联同步响应
- **作业系统**：长任务（文件传输、Shell 等）挂统一 JobRuntime，可列出/查询/终止
- **模块系统**：能力以模块交付（运行时装载/卸载，模块命令随对象生命周期注册）
- **配置契约**：编译期默认 < `SetConfig` 远程下发（运行时可覆盖）；敏感字段落盘加密、
  释放时擦除
- **加密**：libsodium 后端（会话密钥、静态混淆、死投递加密），绝不自研密码学

## 4. TeamServer

- Go 实现，单进程承载 API、beacon 端点与控制台静态资源
- 多操作者会话模型；命令分发与轮询（check-in）语义、任务队列
- 数据落 SQLite；TLS 材料由内置工具生成
- 通道端点与 Agent 的通道链一一对应（HTTPS 为主干，DNS/ICMP 等按需）

## 5. 设计原则（贡献者必读）

1. **单一事实源**：同一行为只允许一处权威实现（配置构造、帧构造、通道物化皆如此）
2. **注册点唯一**：核心命令只在核心注册点注册；模块命令随模块对象生命周期
3. **fail-closed**：安全相关判定存疑时一律拒绝（掩码门、通道自检、畸形输入）
4. **不自研加密/随机数**：一律走库封装
5. **纯函数优先**：帧分类等判定逻辑与状态推进解耦，可独立测试
6. **注释写"为什么"**：注释解释决策与坑，不解释语法
